Engines

Choose Your ML Engine

Same GStreamer elements, same pipelines. Pick the engine that matches your hardware via the engine-name property.

🔥

PyTorch

Default engine with full GPU and CPU support. TorchVision model zoo, HuggingFace Transformers, and Ultralytics YOLO — all battle-tested.

⚡

ONNX Runtime

CPU and GPU inference via ONNX Runtime. Set engine-name=onnx and point to any .onnx model. Automatic YOLO anchor-free NMS decoding built in.

🔷

OpenVINO

Intel-optimized inference on CPUs, iGPUs, and dGPUs. Set engine-name=openvino and point to an OpenVINO IR .xml model file.

🚀

TensorRT

NVIDIA TensorRT through ONNX Runtime. Set engine-name=onnx and device=tensorrt-fp16. The engine is built once and cached.

📡

LiteRT (TFLite)

Lightweight inference for edge and mobile. Set engine-name=tflite and point to a .tflite model. NHWC input by default — no format flags needed.

📊

TensorFlow

SavedModel format for TensorFlow ecosystem compatibility. Set engine-name=tensorflow and point to a TensorFlow SavedModel directory.

🚀

Apache TVM

Compiler-optimized inference via Apache TVM. Set engine-name=tvm and point to a compiled TVM .so module.

💫

tinygrad

Minimal-dependency inference with tinygrad. Set engine-name=tinygrad for lightweight GPU/CPU execution with automatic kernel optimization.

🍏

Apple MLX

Apple Silicon native inference via MLX. Set engine-name=mlx for unified memory GPU/CPU execution on M-series chips. Supports mlx-lm text generation.

📱

ExecuTorch

Meta’s ExecuTorch runtime for on-device inference. Set engine-name=executorch and point to a .pte model.

🤖

llama.cpp

GGUF model inference via llama-cpp-python. Set engine-name=llamacpp for efficient quantized LLM inference on CPU or GPU.

🔬

JAX / Flax

Google JAX with XLA compilation. Set engine-name=jax for JIT-compiled inference with automatic hardware acceleration on GPU, TPU, or CPU.

🔴

AMD MiGraphX

AMD’s graph inference engine for ROCm GPUs. Set engine-name=migraphx and point to an .onnx model. Optimized compilation with fp16 quantization support.

⚙

IREE

Compiler-based ML runtime (AMD/Google). Set engine-name=iree for optimized inference on ROCm, Vulkan, CUDA, or CPU via ahead-of-time compilation.

🔮

NCNN (Vulkan)

Lightweight inference with Vulkan GPU support. Set engine-name=ncnn for GPU inference on AMD, NVIDIA, or Intel — no ROCm or CUDA required.

Agents

Give an LLM Agent Eyes and Ears

mp-mcp is a Model Context Protocol server over stdio. It runs a GStreamer pipeline in-process, so an agent in Claude Code, Claude Desktop or any MCP client can start a pipeline, read what it sees, and tune it while it runs.

Tools

start_pipeline, pipeline_status, stop_pipeline, latest_metadata, set_property, get_property, list_elements, inspect, search_video.

Results

End the pipeline with mp_metasink. Every record it posts, detections, alerts, transcripts, reaches the agent through latest_metadata.

Setup

uv sync --extra mcp
claude mcp add modelpipe -- \
  /path/to/modelpipe/.venv/bin/mp-mcp
Advanced Features

Built for Real Pipelines

Production features that make ModelPipe more than a demo — it’s a framework.

🎯 Multi-Object Tracking

Built-in tracking with mp_yolo. Set track=True and get persistent track IDs across frames with no extra elements.

📊 Multi-Engine Support

Switch engines with a single property: engine-name=onnx, engine-name=openvino, engine-name=tflite, engine-name=tensorflow. Same pipeline, different hardware.

🔀 Multi-Stream Batching

Use mp_streammux and mp_streamdemux to batch multiple video streams through a single model for GPU-efficient multi-camera inference.

🔊 VAD Gating

Voice Activity Detection with gate=true silences non-speech audio before transcription, reducing Whisper latency and false positives.

💬 Qwen VL + LLM Pipelines

Chain mp_caption_qwen (Qwen2.5-VL-3B-Instruct-AWQ) with coalescehistory and mp_llm (Qwen3-0.6B) for real-time video narration with caption history summarization.

🎵 Audio Separation

Demucs vocal isolation (mp_demucs) cleans audio before transcription for dramatically better accuracy in noisy environments.

🌐 Transcribe → Translate → Speak

Chain mp_whispertranscribe → mp_mariantranslate → mp_whisperspeechtts for end-to-end speech-to-speech translation in one pipeline.

🤖 Agent Access over MCP

mp-mcp is an MCP server that runs a pipeline in-process. An LLM agent starts it, reads detections and transcripts from mp_metasink, and changes element properties while it runs.

⚖ Cascade Gating

only-on=alert on any video element runs it only on the frames a cheap detector flagged. YOLO decides, the VLM answers.

🔍 Search Footage by Text

mp_embeddingsink indexes CLIP embeddings, and an agent asks search_video("a red van at the gate") over MCP to get timestamps back.

🎥 Alert Clips

mp_alert tags the frame, mp_alertrecorder writes the seconds around it to a file. No external recorder, no polling.

📨 Kafka Integration

Stream inference metadata to Kafka topics with mp_kafkasink. JSON schema validation, configurable broker and topic, Docker-ready setup.

⚡ Frame Stride

Reduce compute with frame-stride=N on heavy elements like depth estimation. Process every Nth frame and pass others through unchanged.

📊 Batch Processing

Set batch-size=4 on detection elements to batch multiple frames into a single GPU call for higher throughput.

🔥 CUDA Acceleration

Set device=cuda or device=cuda:0 on any element. Automatic GPU memory management and model caching.

Python Without the GIL

On the g2g backend, each Python element runs on its own OS thread. On free-threaded CPython 3.14t with the GIL off, those threads run Python at the same time. Experimental, tested with YOLO and mp_tracker on CUDA. Setup in FREE_THREADING.md.

🔬 ONNX Post-Processing

Automatic YOLO anchor-free NMS decoding with post-process=anchor_free. No manual post-processing code required.

Example Pipelines

Copy, Paste, Run

Real pipelines you can run right now. Every example works with mp-launch.

Alerts

Detect, Alert, Record, Log

YOLO detections raise an alert, the recorder writes a clip, the sink logs every frame as JSON.

python mp-launch.py filesrc location=video.mp4 \
  ! decodebin ! videoconvert ! videoscale \
  ! video/x-raw,width=640,height=480 \
  ! mp_yolo model-name=yolo11m device=cuda \
  ! mp_alert rules='{"class":"person","min_score":0.7}' \
  ! mp_alertrecorder location=alert-%s.webm \
  ! mp_metasink location=people.jsonl

Multi-Stream

Mux/Demux Pipeline

Batch two video streams through one model.

python mp-launch.py \
  filesrc location=cam1.mp4 ! decodebin \
  ! videoconvertscale \
  ! video/x-raw,width=640,height=480 \
  ! mp_streammux name=mux \
  filesrc location=cam2.mp4 ! decodebin \
  ! videoconvertscale \
  ! video/x-raw,width=640,height=480 \
  ! mux. \
  mux. ! mp_yolo device=cuda \
  ! mp_streamdemux name=demux \
  demux. ! autovideosink \
  demux. ! autovideosink

Extensibility

Build Your Own Plugins

Create custom elements that inherit from ModelPipe base classes and run on either backend. Use the same inference engines and model loading code.

my_plugins/python/my_detector.py 
from base_objectdetector import BaseObjectDetector
from gi.repository import GObject, Gst

class MyDetector(BaseObjectDetector):
    __gstmetadata__ = (
        "My Custom Detector", "Video/Filter",
        "A custom object detector", "Your Name",
    )

GObject.type_register(MyDetector)
__gstelementfactory__ = ("my_detector", Gst.Rank.NONE, MyDetector)
Environment Setup 
# Framework first (provides base classes on sys.path), custom second
export GST_PLUGIN_PATH=$HOME/src/modelpipe/plugins:$HOME/my_plugins:$GST_PLUGIN_PATH
export PYTHONPATH=$HOME/my_plugins/python:$PYTHONPATH

# Verify your element
gst-inspect-1.0 my_detector

Platforms

Run Everywhere

ModelPipe runs on Linux, Windows, and macOS with GStreamer, and on systems supported by Glass2Glass.

🖥

Linux (Ubuntu / Fedora)

Native host installation with distribution GStreamer packages. Full GPU support with NVIDIA CUDA. Tested on Ubuntu 24.04, Ubuntu 26.04, and Fedora 42.

🐳

Docker

Pre-built Dockerfiles for Ubuntu 24.04, Ubuntu 26.04, and Fedora 42. NVIDIA Container Toolkit for GPU pass-through. CPU-only mode available.

💻

Windows

GStreamer and its Python bindings from the gstreamer-meta wheels, with Python 3.10 or later. NVDEC decode, CUDA inference and the overlay on CUDA frames. No Vulkan.

🍎

macOS

GStreamer and PyGObject from Homebrew. On Apple Silicon, the MLX engine and the ONNX Runtime CoreML provider with device=coreml.
